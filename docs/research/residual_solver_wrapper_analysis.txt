================================================================================
COST-BENEFIT ANALYSIS
================================================================================

Option A: Full Wrapper Refactoring
  Costs:
    - 180 hours of engineering time (~22.5 developer days)
    - Breaking changes to 17 popular models
    - Ongoing maintenance burden for standard interface
    - Testing and validation overhead
    - Documentation updates
  Benefits:
    - Consistency with latent_ponder pattern
    - Ability to compose residual_solver with any base model
    - Fair ablation studies (e.g., "gru vs gru+residual")

  Code reuse in residual_solver:
    - Only initial encoding step (~10% of model)
    - Refinement loop (90%) is unique to residual solver

  ROI Assessment: POOR
    - Massive effort for minimal code reuse
    - Benefits apply to <50% of models
    - Breaks popular existing models

Option B: Pluggable Encoder
  Costs:
    - ~20 hours to implement
    - Slight increase in model complexity
  Benefits:
    - Some flexibility (MLP vs GRU vs Transformer initial encoding)
    - No breaking changes
    - Incremental improvement
  ROI Assessment: GOOD
    - Low effort, tangible benefit
    - Can be added later if demand exists

Option C: Status Quo (Standalone)
  Costs:
    - Inconsistency with latent_ponder
  Benefits:
    - Zero additional engineering effort
    - Cleanest architecture for purpose-built model
    - No breaking changes
  ROI Assessment: EXCELLENT
    - Immediate readiness
    - Appropriate for residual solver's unique architecture

================================================================================
CRITICAL OBSERVATIONS
================================================================================

1. The wrapper pattern is NOT a good fit for most AirTrace models:
   - 53.1% lack encoder/decoder separation
   - Many SOTA models (timer, timesnet, tft) use integrated architectures
   - Only seq2seq models naturally expose encoder/decoder

2. Popular models require refactoring:
   - gru_ar, lstm_ar (main RNN workhorses)
   - transformer, tcn (core architectures)
   - Modern SOTA models (timer, timesnet, tft)

3. Foundation models have complex internal structure:
   - chronos_bolt, moirai (tokenization, patching)
   - lag_llama (diffusion sampling)
   - Wrapping these would add significant complexity

4. Residual solver's unique requirements:
   - Needs residual estimation R(y, x, h)
   - Needs update network U(r, h)
   - Needs residual-aware halting Halt(h, r, ||r||)
   - Only 10% overlap with base models (initial encoding)
